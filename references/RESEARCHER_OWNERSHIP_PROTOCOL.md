# Researcher ownership protocol

Status: Slice 0 design contract with Slice 4 method/tool learning implemented via
schema 3 and `scripts/tutor_session.py`; ownership runtime remains pending Slice 5. `LEARNING_PROTOCOL.md`,
`KNOWLEDGE_MODEL.md` and `TUTOR_PLANNING.md` remain the human-learning authorities.
`EVIDENCE_FORMAT.md` remains scientific evidence; ownership evidence never replaces it.

## Meaning and selective obligations

An ownership gap is consequential machinery used in the researcher's work whose
personal explanation, method choice, operation, modification or limitations have
not yet been demonstrated. Ownership is not memorization of entire libraries.
Reference retention targets can be appropriate: recovering exact syntax is compatible
with understanding what a tool does, why it is used and how it can fail.

Relevant introductions include an equation, estimator/statistical test, simulation
model, preprocessing choice, ML/QML architecture, unfamiliar method/tool or important
interpretation. Do not create gaps for trivial engineering details or every API.
Record the affected claim/artifact/decision, consequence, introduced_by provenance,
required_for context and relevant capability references. The human may refine the
required capabilities; agent introduction does not automatically create unlimited
learning obligations or prove a gap in a capability already demonstrated.

Ownership gaps do not block scientifically valid research by default, invalidate
EvidenceAtoms, revoke approved experiments or automatically stop implementation.
Surface them when the researcher claims personal understanding, prepares a
presentation/paper, makes major decisions, modifies the work independently or
defends it. Scientific blockers still follow research triage independently.

## Evidence and storage boundary

Ownership evidence is actual human-learning evidence: learner answer/action,
capability contract, scope/dimension/context, verdict, assistance and freshness.
An agent's explanation, task completion, note existence, confidence or scientific
EXACT_SUPPORT is not evidence that the researcher understands it.
Missing evidence means unknown, not proven inability. Keep explanation, derivation,
transfer and project application distinct from method understanding, tool operation
and implementation navigation. Never collapse them into a single mastery scalar.

Reuse one canonical capability ledger per capability. Proposed ownership records
store provenance, requirements and references to those ledgers; readiness is derived,
not another saved grade map. New dimensions use the supported opt-in schema 3
extension in Slice 4: the current strict schema-2 parser does not accept them.
Do not write proposed fields into existing learning frontmatter in Slice 0.
Keep legacy scope unknown; no historical attempt is relabelled automatically.

## Learning integration and interruption contract

Research stage 19, Learn again, should teach what/why/how, assumptions, alternatives,
tool/library behavior, reproducible operation, inspection, code location, modification
and failure modes for consequential work. Map only relevant methods/tools to
capabilities; for example an estimator choice may need method reasoning separately
from operating its library or navigating its implementation.

Learner questions are first-class interruptions. The implemented tutor branch checkpoint
preserves original target, current lesson stage, unresolved question, prerequisite
branch and return point, including nested interruptions. Answer the question, verify
uncertain content when needed, then resume or explicitly renegotiate the target.
Useful internal categories include CLARIFICATION, DEEPEN, PREREQUISITE, CHALLENGE,
METHOD, TOOL, TRANSFER, PROJECT_APPLICATION and OFF_TOPIC_BRANCH; natural questions
need not be forced into a rigid label or exposed taxonomy.

Learner-generated questions do not count against the diagnostic/probe budget;
only tutor-initiated assessment questions count, including assessments inside an
interruption. Do not evade the budget through branches. A learner question may
be assessment evidence only when its actual answer/reasoning satisfies an explicit
capability contract with honest assistance and verdict. Casual conversation and
newly revealed solutions must not become fake mastery or delayed retention.

## Compatibility and acceptance

Validity and mastery are separate: a supported claim can have unknown method/tool
readiness, while a demonstrated capability cannot make an unsupported claim valid.
Existing learning schemas, retention choices and scientific approval remain intact.
Prefer versioned ownership requirement records linked to canonical research and
learning artifacts rather than expanding strict research frontmatter unnecessarily.

Slice 4 tests interruption/resumption and separate concept/method/tool evidence.
Slice 5 tests selective ownership gaps, unknown evidence, actual assistance,
context-specific readiness and noninterference with accepted scientific records
and approved work. No automatic real-vault writes or permanent-note promotion.
