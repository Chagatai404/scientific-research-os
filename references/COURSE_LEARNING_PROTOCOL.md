# University course learning protocol

Ordinary coursework is learning, not a research project. Build on
`LEARNING_PROTOCOL.md` for state, retrieval evidence, bounded probing, retention
targets and human promotion. Do not invoke the full `RESEARCH_PROTOCOL.md` merely
because the learner is studying a university course. Only an explicit transition
to a substantive research question activates that workflow and its approval gates.

## Course cycle

1. Inspect the available syllabus and course outcomes. Identify the course ID,
   term, assessment structure and learner-entered dates; do not invent missing
   requirements. Ask for missing material only when needed for the current work.
2. Map topics, sequence and prerequisites to existing capability IDs. Use one
   record even when a capability belongs to several courses, projects and goals.
3. Check current knowledge and relevant retrieval evidence with bounded probing.
4. Study the lecture/topic: prepare verified course facts before live questions;
   motivate concepts, derive when useful, and connect to foundations.
5. Practice using problems at the course's level. For homework support inspect the
   learner's attempt, offer proportionate hints and explanations, and respect
   stated assignment rules. Record assistance rather than claiming unaided success.
6. Check retrieval/application before revealing solutions; recognition alone does
   not establish retention. Repair weak prerequisites needed for the current topic.
7. Use assignment/exam feedback to identify particular mistakes and capabilities.
   A grade or submitted solution is not automatically a retrieval-history pass.
8. Update the derived course learning map from capability evidence and choose the
   next useful activity with the learner.

Use this cycle for lecture preparation/review, concept learning, problem solving,
homework support, exam preparation, cumulative review and prerequisite repair.
Exam urgency is a short-term study constraint, not an automatic permanent `core`
assignment. Preserve the learner's existing targets. Recommend core / working /
reference with rationale when useful; leave meaningful choices to the learner.

## Sources for ordinary study

Prefer, in rough order when applicable: official course material, assigned textbook,
instructor notes/slides, authoritative textbooks, primary/official technical
references, then high-quality external teaching resources. Record relevant pages,
sections or problem numbers and distinguish course conventions from alternatives.
Verify uncertain facts before teaching; disclose unavailable material or conflicts.
Do not require literature-scout or source-verifier agents for routine course study.
Disputed, research-level or consequential scientific questions may need the normal
source/research policies. Clarify that transition rather than silently converting
an ordinary course session into research.

## Records and views

Optional schema-1 `courses: ["stat-xxx"]` uses the same stable-ID syntax as projects
and goals. Membership is explicit, never inferred from domain/project overlap.
Use `knowledge.py --root <notes> --course stat-xxx` to select members and include
transitive external prerequisites. State, retention target, freshness, frontier
and diagnostics use the existing evidence model; there is no course mastery ledger.
A capability can have one domain and multiple courses, projects and goals.

`15_Course.md` and `16_Course_Session.md` are optional plain-Markdown interfaces.
Link evidence records instead of copying their histories. Neither Obsidian nor
the graph generator is required: chat or another learner-selected workspace works.
Do not create a research-project note just to hold coursework. Course maps and
session explanations do not automatically become permanent concept notes.
