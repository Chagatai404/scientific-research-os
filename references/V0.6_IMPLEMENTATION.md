# v0.6 — Connected Research & Learning OS

## Frozen contract

Baseline: v0.5.0, main commit `349f01d`. Implementation branch:
`agent/codex/v0.6-connected-research`. Clean checkout; no additional worktrees
or configured shared coordination state found. No parallel Claude ownership found.

Objective: expose deterministic persistent research and learning state, explicit
evidence/provenance links, bounded context and mechanically available transitions.
The human chooses research directions, conclusions and consequential learning choices.

Canonical state remains Markdown, strict frontmatter, JSON and Git. Research,
learning and code graphs remain separate semantic graphs linked only explicitly.
Graph/frontier/dashboard state is derived, never a manually duplicated registry.
Research tracking is opt-in `research_schema: 1`; historical notes remain untracked.
Learning schema 1 and all v0.5 evidence, compute and methodology behavior survive.
Authorization is separate from experiment readiness. Completion, valid manifests,
graph edges and metrics never establish scientific acceptance.

Tutor consults evidence and prerequisite closure, internally distinguishes TESTS,
ASSUMES and INTRODUCES, and defines unestablished terminology before requiring it.
Mention, teaching, demonstration and retention remain distinct. Visual viewing is
not retrieval; MCQ recognition alone is not retention. Reusable trusted visuals
need verified provenance; rendering alone is insufficient. Schematics make no
unsupported quantitative claims and animations must not fabricate motion.

Schema: four primary entities (research-question, hypothesis, experiment,
research-decision), explicit project membership, type-specific states and links.
Cross-links reference EvidenceAtoms, manifests, artifacts, learning dependencies,
visuals and code; they do not copy those records. Human decisions are explicit.

Scope is the ordered slices below. Exclusions: databases, embeddings/RAG, servers,
daemons, mandatory cloud/plugins/Graphify, dependency installation, vault mutation,
bulk migration, permanent-note promotion, experiment execution/prioritization,
autonomous acceptance/direction selection and paper generation. No merge, tag or
publication. Standard-library Python only. No real-vault reads or writes needed.

Each slice: inspect existing implementation, make only scoped changes, add focused
checks, run full unittest discovery and `python scripts/validate.py`, inspect
diff, repair regressions, commit and record results here. Commit IDs are recorded
in the following slice entry (a commit cannot include its own hash).

VERSION remains 0.5.0 until all release gates pass: full suite and validator,
all provider installer dry-runs, unchanged pre-v0.6 regressions, optional adapter
absence, legacy compatibility, standard-library independence, and manual inspection
of connected example validate/status/frontier/graph/context, knowledge query,
health and bootstrap outputs. Verify a fresh agent can recover relevant research,
learning, terminology, visual, evidence, manifest and code state without invented
mastery or conclusions. Then update VERSION to 0.6.0 and commit separately.
