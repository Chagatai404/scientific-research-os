## Boundaries

| Layer | Responsibility |
|---|---|
| Canonical skills/protocols | Scientific judgment and validation |
| Tool profiles/guides | Software-specific knowledge and discovery metadata |
| Runtime probes | Observed facts about the environment |
| Experiment/project configuration | Explicitly declared scientific choices |
| Derived values | Computations with recorded observed/declared inputs |

**Runtime discovery must never silently infer a scientific configuration choice.**
Python/OS, installed package versions, Geant4 executable/binding versions, known
dataset environment variables and safely queried accelerator availability are
observations. Physics lists, cuts, geometry, beam distributions, splits, features,
architectures, optimizer/rate, quantum encoding, ansatz, qubits, shots, noise and
backend selection are declarations. Unavailable facts remain UNKNOWN.

Use standard-library Python and JSON, with generic observed/declared/derived
mappings; no database, server, automatic dependency installation or scheduler.
Tool profiles are strictly validated TOML plus Markdown guides. Permit only
code-owned allowlisted probe argument arrays with shell=False, never arbitrary
commands, scripts, imports or interpolation supplied by profiles. Package
discovery uses distribution metadata without importing scientific frameworks.
Optional accelerator queries must be explicit and code-owned, never workloads.
Availability describes discovered components, not operational/scientific validity.

Project-pinned versions take precedence over the latest available release.
No probe authorizes experiments; existing plan → approval → build/experiment
semantics govern execution. Successful execution is not scientific validation.

## Deployment and bounded slices

The current installer discovers every top-level SKILL.md and uniformly bundles
all references. Preserve this architecture. Add only geant4, ml-experiment and
qml-experiment as global skills. Ship framework knowledge as optional tool packs;
copy self-contained helpers/packs into relevant installed skills so they work
outside the source repository. Generate equivalent Claude/Codex policy.

Implement and commit in order: 0 contract; 1 computational protocol; 2 manifest;
3 tool-pack system; 4 Geant4; 5 ML; 6 QML; 7 HEP bridge; 8 canonical routing;
9 installer; 10 regression hardening; 11 documentation/examples; 12 release gate.
Run the full existing unittest suite and validator for every slice, add focused
tests, inspect diffs and report results. VERSION stays 0.4.5 until release gates
pass; then commit 0.5.0. Do not merge, tag or publish.

Use mocks for packages, PATH, subprocess and environment. No network, GPU, QPU
or scientific software is required by tests or repository validation. Review
generated layouts in temporary directories and dry-run every installer target.
Defer experiment trackers, workflow engines, cloud/HPC/QPU automation, new
framework families, Obsidian plugins and cross-device synchronization.
Stop only for material conflicts with the approved invariants, using A–D triage;
ordinary reversible engineering choices remain within approved scope.
