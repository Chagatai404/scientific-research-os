## Motivation, decisions and rejected alternatives

Reliable literature needs identity and actual access to remain visible across
extraction, verification and synthesis. Reading or finding a paper is not claim
verification. Use existing catalog normalization/aliases and EvidenceAtom envelopes,
comparison semantics, source values and independent receipts. Reject a second
evidence schema, a single confidence ladder and automated semantic truth scoring.

Authenticated access is a capability returning sanitized documents/outcomes from
an already-authenticated user environment. Reject password/cookie/token forwarding,
institution-specific login logic, internal secrets storage and automatic licensed
bulk retrieval. Institutional availability does not establish permitted automation.

Durable tasks record execution and dependencies, while the research protocol owns
scientific ordering and permission. Adapters launch/collect where supported; manual
execution is a valid fallback. Reject provider APIs in the canonical scientific
model, a database/daemon/heavy framework, hidden experiments and majority-vote
verification. Atomic files, bounded outputs and explicit writer reservations are
planned; stale RUNNING work requires reconciliation before retry.

Ownership requirements selectively link consequential work to actual capability
evidence. Reject copied mastery maps, obligatory memorization, endless trivial tool
targets and a learning prerequisite that revokes research authorization. Defense
is a derived view with independent scientific-support and personal-readiness axes;
reject a global readiness score or viva success as scientific acceptance.

## Security and scientific independence boundaries

Never persist passwords, VPN credentials, cookies, tokens, authentication headers,
login forms, private session artifacts or secret URLs in any Research OS output.
Capabilities must reject/sanitize outputs before logging or agent exposure. Licensed
automation permission is explicit; no paywall/CAPTCHA bypass or unbounded retrieval.
Paths are confined with symlink checks; inputs bind immutable versions; writes use
isolation/reservations and recoverable atomic files. Live environments are outside
implementation scope until explicitly authorized.

Scout conclusions cannot leak into supposedly independent verifier/reviewer contexts.
Declared independence groups are not proof: record actual exposure and limitations.
Shared verified artifacts may support coordinated work without being new independent
corroboration. Task COMPLETE does not imply EXACT_SUPPORT, approval, accepted research
or learner mastery. Approval references and authorized scope must be checked before
BUILD/EXPERIMENT launch, restart or retry; background work cannot widen permission.

### Architecture and decisions

`scripts/literature_check.py` adds a read-only stdlib schema-1 literature manifest.
It references existing EvidenceAtom JSON paths/content fingerprints instead of
extending or duplicating authoritative scientific evidence. Existing atom parsing,
fingerprint coverage, receipts, CLI behavior and paper catalog writes are unchanged.
New fields remain outside strict research/learning/catalog schemas; legacy records
remain valid without a manifest. Use the literature gate for manifest-linked synthesis.

Paper identity reuses catalog normalization/aliases/matching: DOI → arXiv → other
stable ID → explicit title/year fallback. Strong-ID and bibliographic conflicts,
weak ambiguities and malformed IDs are diagnosed. Duplicate projections retain
URLs/member IDs; existing catalog-format IDs survive enrichment rather than being
rehashed. Weak matches remain review-dependent. Confirmation is supplied metadata
with a source, not a network registry lookup or invented authors/year.

Access, locator region and explicit body dependence bind to the current atom/source
version. Consequential claims declare required envelope and assumptions. Scope
fingerprints reuse atom envelope fields plus source version/evidence type and
assumptions; they never grant support. Metadata/snippets, full-text reading and
independent support remain distinct observations. Limited abstract-only exact support
is always qualified. A body-dependent verified claim cannot use abstract-only access.

Conflict comparisons carry source-linked claim IDs, applicable checks and explicit
reviewer rationale/exposure/relation. All six contract classes are represented.
Both atom and scope fingerprints bind a conflict review; changed claim content or
assumptions invalidate it until refreshed. This preserves the Slice 0 snapshot contract.
Mechanical checks reject genuine conflict over unmatched observables, regimes,
conventions, units, relation orientation, evidence quality or missing review checks.
Genuine/unresolved disputes remain qualified, and derived factual exports require
all their inputs in the unqualified factual set. Different maxima are scope
differences; equation equivalence still requires scientific reconstruction.

The unit checker uses a small exact vocabulary; it flags dimensional incompatibility
or needed conversion/review without evaluating equations or converting values.
Semantic citation drift and conflicts remain source/human judgments. There is no
automatic receipt creation, truth grading, agreement voting or conclusion acceptance.

`--handoff` provides an allowlisted claim/source/minimal-scope context and assumptions
to check, withholding scout notes, source values/excerpts and verdict/receipt fields.
It cannot remove bias embedded in prose or prior conversation; honest exposure and
fresh independent dispatch still matter. `--facts-only` exports full-text exact
facts separately from limited/TRANSFERRED/disputed support; errors suppress both
collections. JSON is ASCII escaped for portable Windows pipes; content hashes use
canonical UTF-8. File/record limits and confined nonsymlink paths bound reads.

Default operation is a plan with no writes/network. `--apply` permits local

`--download`, reviewed permission and matching version. HTTPS/public URL checks
apply before every request/redirect, including robots redirects; robots denial,

Unknown fields, recognizable credentials and private query/fragment/encoded URLs
are rejected. CLI errors and runtime failures use fixed codes rather than provider
exceptions, raw paths, headers or diagnostics. Only sanitized origins are recorded
for retrieval; reviewed public bibliographic URLs remain ordinary paper metadata.
The helper does not read browser state, environment secrets, institutional forms,
VPN settings or external accounts. Adapters must sanitize before handing anything
to Research OS; agents are instructed never to inspect raw sessions/responses.

PDFs are bounded at 50 MiB and confined to the selected inbox without symlinks.
Checked bytes are transiently staged for the existing authorized-local importer.
Screening, canonical IDs/aliases, single physical PDF, catalog, indexes and hash
protection stay with `paper_library.py`, which is unchanged. Unavailable useful
papers retain citation metadata and appear in the unavailable-PDF index. An access
lock complements the importer lock. A per-library durable file allows at most one
attempt per 60 seconds and ten per rolling 24 hours, including failed attempts;
validated duplicates bypass retrieval and rate consumption. Corrupt/future/out-of-
order guard state fails closed. No automatic lock removal, daemon or database.

Sanitized `.access/PAPER-<id>.access.json` sidecars bind paper ID, public alias,
document version, basis, origin, retrieval method, automation permission, saved/
available state, outcome/reason code, confined document path and SHA-256. Legacy
cached PDFs with no version-bound sidecar are not assigned the requested version;
manual review is required. Existing PDFs are never silently replaced.

Literature claims may opt into `access_ref: {record_ref, document_ref}`. Both paths
are relative to the check root, with JSON access-record/PDF artifact suffixes;
permitted explicit copies support a project-root manifest. The checker binds actual
bytes to catalog identity/alias/version/hash, carries provenance into facts and
qualified exports, and rechecks the snapshot for minimal verifier handoffs. Invalid
bindings fail closed without echoing rejected reference payloads. Saved documents
never create reading declarations, independent receipts or accepted research claims.
Old manifests without this field, EvidenceAtom v1 and legacy learning/research
schemas remain supported. Both provider bundles install identical helper dependencies
and policy; examples are validated without network or global installation.

### Architecture and behavior

`scripts/tasks.py` adds a stdlib schema-1 project-local task DAG in
`.research-tasks/state.json`. `plan` is dry-run without `--apply`; ready/status are
read-only projections. Explicit start/collect/cancel/retry/reconcile mutate durable
execution state under an exclusive lock and atomic replacement. No central database,
daemon, shell evaluation, arbitrary goal execution or provider dependency is added.
The 20-stage research lifecycle and independent evidence/learning state are unchanged.

Specs bind task/role/goal/stage, canonical research/input refs, dependencies,
independence group, declared context, permission scope, provider and writer
workspace. Runtime holds actual UTC event timestamps, attempts/history, local job
ID, result/artifact bindings, actual collected context, sanitized failure and cancel
request. Unknown fields, duplicate IDs/refs, cycles, dangling dependencies, escaping/
symlink paths and changed hashes fail closed. Missing not-yet-ready inputs wait.
Existing specs are never silently rewritten: changed inputs need restoration or a
new ID. Bounds: 100 tasks, 20 attempts/history entries, 30 refs/list, 2 MiB JSON,
50 MiB artifacts. Successful shared completed dependencies are validated once per
projection, avoiding exponential DAG walks; subsequent operations recheck afresh.

Source verifiers are read-only stage-4 tasks with claim/source/minimal-scope inputs,
bounded exposure and an independence group. Launch packets omit dependency results,
canonical research links and earlier attempt/coordinator history. Collection records
actual exposure and rejects purported independent full-history work. Scientific
role names retain stage routing. A COMPLETE task is execution collection, not a
source verdict: stage-8 synthesis needs a source-verifier dependency and valid bound
EXACT_SUPPORT/TRANSFERRED EvidenceAtoms (including derivation inputs). TRANSFERRED
stays qualified; literature checking still owns access/conflict factual synthesis.
Stage-7 reconciliation requires external discovery. The coordinator must declare
scientifically sufficient dependencies; task goals are not semantic proof of that.

Build/experiment and every scientific write/run require a current hash-bound
recorded human approval of a presented immutable plan, task/stage, exact write/run
scope and workspace. Checks run during planning and again before launch, collection
and retry. Permissions do not inherit from dependencies. The helper never writes an
approval, creates scientific receipts, grades mastery or accepts research conclusions.
An approval record is a human attestation, not a cryptographic issuer proof.

Writers require an existing isolated Git worktree of the project repository, exact
