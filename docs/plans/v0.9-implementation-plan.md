## Architecture and prior decisions

Reviewed v0.7/v0.8 implementation records, v0.8.5 HTML plan, HTML design record,
v0.8.6/v0.8.7 changelog, canonical parsers, installation and regression infrastructure.
Work happens on a clean branch of `main`; other worktrees (Codex's `.codex/worktrees/*`)
are not modified. No user research or learning data is changed: tests use temporary
vaults and synthetic fixtures only.

Preserve five authorities: capability ledgers, research records, code, paper catalog,
and session state. Reuse `knowledge.discover/query`, `research.validate/enrich/context`,
`tutor_plan.plan`, `tutor_contract`, `tutor_session.replay`, `paper_library.catalog/match`,
EvidenceAtoms and computational manifests. Rendering, context receipts and verification
reports are projections/artifacts, never replacement authorities.

The new context service will expose versioned requests/receipts, source fingerprints,
bounded explicit relationships and failure diagnostics. Workflow entrypoints must
validate receipts before dependent operations. New-session bootstrap must not depend
on session existence. Essential unavailable context blocks dependent actions; genuinely
empty readable roots remain distinguishable. Provider adapters share this contract.

EvidenceAtom already recomputes finite Decimal sum/product/ratio
(`validate_evidence.py:155–217`) with input fingerprints and value/unit bindings.
Reuse that mechanism; the gap is richer calculations, dimensional algebra and scoped
independent verification, not an absence of all executable arithmetic.
Verification will execute bounded reviewed calculations and record input assumptions,
environment, tolerances and unresolved obligations in computational provenance. A
successful process or structurally valid manifest is not scientific verification.
Neither majority agreement nor optional-library absence settles a scientific claim.

## Slice 1 record: Context Kernel (implemented)

`scripts/context_kernel.py` (stdlib, read-only) retrieves a bounded subgraph over the learning graph,
research graph, project note, code graph, paper library, visual registry and earlier sessions, and writes a
schema-1 receipt: per-source status (`ok / empty / missing / invalid / unavailable / not-configured /
not-applicable`), content fingerprints, truncation flags, limitations and a tamper-evident `receipt_id`.
Contract: `references/CONTEXT_PROTOCOL.md` (a test keeps its workflow table equal to `POLICY`).

Enforced, not advised: `html_sessions.py create` runs the preflight and refuses (exit 2, nothing written) when
essential context is blocked; `add_question`, `append_session` and `review_response` (with new teaching) require the
bound context to be current, rebuilding a stale binding and refusing a blocked one; `tasks.py` stages 7, 8, 14, 15
require one fresh `context-receipt` input. Historical sessions without a binding keep working and can be adopted
with `html_sessions.py context SESSION --bind`. The Obsidian host keeps the binding (local paths) out of the page.
`session_context` is now a thin caller and works before the session exists (complaint 7 test repaired).

Known limitations: the receipt proves what was consulted and that it is unchanged, not that a model understood it;
only the gated actions make skipping it fail. Freshness fingerprints whole source trees (cheap stat digest first);
visuals and earlier-session scans are advisory and not fingerprinted. Stage 3 literature discovery is deliberately
ungated (neutral discovery). Live provider omission rates remain live-only.

## Slice 2 record: Scientific Verification Engine (implemented)

`scripts/scientific_verify.py` (stdlib core; sympy, numpy, scipy, mpmath and statsmodels are optional independent
cross-checks, never required; pint/astropy absent here so a small SI dimension algebra is built in). A spec lists a
claim, its declared assumptions/domain/tolerance and executable *checks*; the engine runs them and records a scoped
outcome. It never "verifies" free text: claims without executable obligations are `not-checked`, and a missing
obligation is reported as unresolved, never silently upgraded. Expressions are parsed from a whitelisted AST and
interpreted (no `eval`, no `sympify`). Outcomes: `verified-in-scope`, `partially-verified`, `invalidated`,
`unresolved`, `not-checked`. Any failed check invalidates; an unavailable optional tool downgrades only when the
check was required and never invalidates; consequential claims need two independent method families and a valid
context receipt. Records (`*.verification.json`, schema 1) embed environment/versions and are re-runnable
(`rerun` reproduces the outcome). Linked to existing evidence by listing the record in a manifest's `artifacts`
and a research record's `artifacts`; `research.py` reports their outcome. Check kinds: evaluate, equivalent,
integral, derivative, limit, dimensional, rate-interval (exact Clopper-Pearson), propagation (with covariance),
resampling-unit, fit-partition, assumption-declared, regime-match, mapping-declared.

Delivered: `scripts/scientific_verify.py`, `references/VERIFICATION_PROTOCOL.md`, `agents/mathematics-reviewer.md`
(new) and strengthened statistics/physics reviewers (three distinct read-only roles, each bound to its context
workflow and required to list what it did **not** verify). The protocol is bundled into seven reviewer roles for both
providers and the engine ships in every installed skill. `research.py` reports linked `*.verification.json` outcomes
beside the evidence and the context kernel retrieves them. 44-case regression fixture (general + AMS ECAL).

Honesty rules that are tested: any failed check invalidates; an unmet required obligation lowers the outcome and is
listed; an unavailable optional library never invalidates or downgrades a correct result; floating-point disagreement
inside the expressions' own running-error bound is not a refutation (adjudicated at high precision, else
`unresolved`); a consequential claim needs two independent method classes (or a second formulation), a
`bounded`/`qualified` reviewer and a fresh review-workflow context receipt, else it stops at `partially-verified`
or is refused. Real defects found by writing the tests: a limit and an identity that naive floating point wrongly
refuted (cancellation); a flag/field name collision (`required`); an unhandled exception type that would have
crashed research-graph loading on a corrupt record.

Known limitations: it checks *structured obligations only* - prose claims without executable checks are
`not-checked`, and `resampling-unit`, `fit-partition`, `regime-match` and `mapping-declared` trust the declared
description of a pipeline rather than inspecting code. No proofs (a theorem needs a proof assistant). Dimensional
algebra covers SI plus a small unit table (unknown unit = error). Exact intervals are binomial only. Independence
classes are coarse. Whether live reviewers write good specs is live-only.

## Compatibility and migrations

- Keep learning schemas 1/2/3, research schema 1, EvidenceAtoms, paper IDs and histories.
- Preserve original Markdown and old HTML/state triples, raw answers, times and reviews.
- Version opt-in extensions; historical missing correctness/assistance stays unknown.
- Any canonical migration needs dry run, exact backup, conflict checks, repeatability
  and rollback tests. Projection regeneration cannot overwrite edited originals.
- Retain opaque sandbox, CSP, bounded authenticated bridge and resource hash approval.
  Navigation grants only a validated host operation, never filesystem access.
- No mandatory paid service; optional plugins fail visibly and gracefully. Do not
  install plugins or deploy to the real vault during isolated fixture development.
- Package import closures in both provider installations and test outside the checkout.

## Dependency and host reconnaissance

System Python metadata: SymPy 1.14.0, NumPy 2.4.6, SciPy 1.17.1,
mpmath 1.3.0; Pint absent. Bundled Python has NumPy 2.3.5 but lacks the other four.
No optional scientific library becomes an unconditional core dependency.
Do not pass untrusted expressions to SymPy `sympify`/`parse_expr`: use bounded
expression trees and explicit constructors.

System Mistune 3.3.4 is a pure-Python BSD-3-Clause parser; evaluate vendoring with
license/version/hashes and standalone installer tests. Prefer one parser producing
derived presentation fragments for all surfaces over divergent Python/JS parsers.
Use an explicitly escaped math renderer and negative tests; older Mistune versions
had a math escaping advisory. Keep original authored strings authoritative.

Read-only plugin manifest inventory: Breadcrumbs 4.21.14 (minimum Obsidian 1.13.0),
Excalidraw 2.28.1 (minimum 1.8.7), Research OS HTML 0.1.0 (minimum 1.5.0).
Manifest presence does not prove enabled/running APIs. Public Obsidian
`metadataCache.getFirstLinkpathDest` and `workspace.openLinkText` support a confined
host bridge. Excalidraw 2.28.1 exposes `createPNG`; optional host-side export can
reuse approved raster resources without admitting arbitrary SVG. Runtime feature
detection and live verification remain outstanding.
