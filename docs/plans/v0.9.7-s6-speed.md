# v0.9.7 S6 — Speed

The researcher's complaint: the voice is not truly live and there is too much waiting. v0.9.6 measurements on the researcher's machine: first sentence about 1.5 s, a 7.2 s sentence back in 3.4 s, Whisper warm 1.1 s. The long pole is the agent's own turn, not the voice, so the common path is made near-instant by doing the work before it is asked for.

## What changed

| Piece | Where | Effect |
|---|---|---|
| Sentence cache in the live worker (bounded; answers cached requests first) | `scripts/voice_adapter.py` | A sentence rendered once is returned with no synthesis |
| `voice.py prefetch` renders the plan's lecture ahead, in play order (first pieces, acknowledgments, rest, repair/extension, anticipated answers) | `scripts/voice.py` | Start the lecture with no synthesis wait; run it while the learner is in probe/handout |
| Phrase-level synthesis: a long sentence is spoken as short pieces (`phrase_chunks` in Python, `speechChunks` in the page, shared cases in `tests/fixtures/plan-cases.json`) | `voice.py`, `board.js` | First sound waits for a short piece, not the whole sentence |
| Worker heartbeat from a thread | `voice_adapter.py` | A long render no longer makes a ready worker look dead |
| Acknowledgment clips pre-loaded and played the moment a question is sent (skippable; never a wait) | `board.js` `preloadAcks/playAck`, `stages.js` | Sound within one frame of sending while the tutor thinks; wording never judges the question |
| Anticipated-question matching (`match_anticipated` / `matchAnticipated`, shared cases) | `session_plan.py`, `stages.js` | A matching prepared answer is offered as a button, never played unasked; the question still goes to the tutor |
| Live requests: at most 3 out; wanted-now before wanted-ahead; ahead never takes the last place | `board.js` | A sentence needed now is never queued behind read-ahead |

## Measurement

Not yet measured. This build step ran in a cloud Linux container with no Kokoro, no Whisper and no audio, so no time-to-first-sound was taken. The tests prove behaviour (cache hits, ordering, request limits, ack timing with fake clocks), not latency. To fill the table on the researcher's machine (scratch folder, never the vault's voice folder; stop with `<dir>/tts-stop`):

```
python scripts/voice.py up --dir <scratch> --only tts --env C:/Users/ASUS/voice-envs/kokoro --voice model_dir=C:/Users/ASUS/voice-envs/kokoro-models
python scripts/voice.py prefetch --dir <scratch> --plan <plan.json> --wait 120
```

| Case | v0.9.6 (before) | v0.9.7 S6 (after) |
|---|---|---|
| First sentence, cold cache | about 1.5 s | not measured |
| 7.2 s sentence, cold cache | 3.4 s | not measured |
| Later sentence, cold cache | not recorded | not measured |
| Any sentence after `prefetch` | n/a | not measured (expected: file read + decode) |
| Question sent → first sound (ack) | tutor turn length | not measured (expected: decode-free, under 100 ms once loaded) |
| Whisper warm | 1.1 s | unchanged, out of scope |

Not done: GPU Kokoro measurement (RTX 4050 is shared with another model; the CPU worker is what runs).
