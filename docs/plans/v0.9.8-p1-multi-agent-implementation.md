## What already exists and what P1 must add

- `tutor_plan.recommendation` supplies canonical bounded advice;
  `learning_preferences.recommend` adds explicit presentation preferences and
  pacing without changing its evidence requirements. Extend this path; do not
  introduce a competing planner or mastery database.
- `session_plan` schema 1 strictly rejects unknown fields. Questions currently
  support one optional `hint`, a `solution`, choice/numeric/short answers and
  criteria. It does **not** yet encode graduated hints, explanation levels,
  practice tiers, source comparisons, Bloom families or analogy mappings.
- `tutor_session.replay` already supplies nested branch/return points, one pending
  assessment, actual answers, criterion reviews, assistance and a shared probe
  budget. Its declaration is distinct from staged HTML state. P1 must explicitly
  connect these at a trusted writer boundary, not silently treat their different
  event formats as interchangeable.
- `html_sessions` owns locked writes, context enforcement, immutable answered
  assessment semantics and frozen lecture paths. `plan_evidence.propose` creates
  a read-only evidence proposal bound to actual question/answer digests and review.
- `stages.js` owns the existing five-stage presentation, native text lesson,
  handout, local pacing and Study advice. Draft sidecars preserve unsent input;
  the companion owns authenticated filesystem operations.
- `terms` already preserves canonical/bilingual identities and term event state;
  `resources` already distinguishes source registration/checking/vetting. Reuse
  these authorities without equating a checked URL with verified scientific content.

P1 is complete only when the behaviors work through prepared content, trusted
writes, rendered interaction, saved learner attempts and review. Policy helpers
or skill prose alone do not complete a slice.

## Team and exclusive ownership

Use at most **four simultaneous agents**, including the coordinator. Before each
wave inspect Git, worktrees, recent commits and the configured shared coordination
state; confirm Claude ownership. Use the existing isolated Codex checkout. All
workers are told they are not alone and must preserve other agents' edits.

| Seat | Responsibility | Exclusive files while assigned |
| --- | --- | --- |
| C: coordinator/integrator | Freeze interfaces, integrate one vertical slice, run integration/browser gates, record commits | `scripts/session_plan.py`, `scripts/html_sessions.py`, `scripts/tutor_session.py`, `scripts/learning_preferences.py`, `scripts/plan_evidence.py`, `assets/html-runtime/stages.js`, `stages.css`, generated runtime bundle, companion, installer inventories, existing shared tests and release/migration docs |
| A: behavior worker | One independent pure validator/projection and its scientific fixtures | Only the new module, new tests and namespaced fixtures listed in its current wave |
| B: behavior worker | Second independent pure validator/projection and its scientific fixtures | Only the different new module, tests and namespaced fixtures listed in its current wave |
| R: independent reviewer | Adversarial contract/science review, acceptance cases, then frozen-diff verification | Read-only production code; new wave-specific acceptance fixtures/tests only when explicitly assigned |

C alone edits shared schemas, writers and runtime. A/B submit bounded modules and
tests for review; they never independently add top-level plan fields or transport
messages. R must not rewrite implementation while reviewing it. Only C commits
the reviewed, tested integration. Run installed-helper copy tests against frozen
source: P0 showed that simultaneous edits can create misleading drift failures.

## Contract checkpoint before parallel coding

C and R first write and test the smallest additive optional prepared-content
contract needed by P1a/b. Proposed location: one optional `plan.pedagogy` container
validated by a new stdlib-only `scripts/pedagogy_contract.py`. This is a proposed
interface, not an existing accepted schema. Freeze names, limits and examples in
`references/SESSION_PLAN.md` before handing modules to A/B. Reassess nesting after
checking actual size budgets; avoid duplicating prompts, solutions or source text.

Each behavior entry must bind an existing target and, where applicable, a prepared
question/segment ID and its content digest. It carries bounded typed metadata,
source references/locators and content version. Metadata cannot override question
criteria, keys, capability scope, dimension, independence or canonical IDs.
Absent metadata retains current behavior. Unknown types/oversized records fail
atomically. No schema bump or migration is assumed until compatibility tests prove
the additive design; old plans remain valid without rewriting their content.

For interaction, prefer existing raw attempts, append-only assistance/checkpoint
events, open questions and attempt-bound reviews. C verifies the exact existing
event allowlists and replay semantics first. If a new event is necessary, define
and test it end to end in Python, runtime and companion together. Hint level must
be reconstructible after reload and bound to the relevant question/attempt; a
hint/reveal can never leave an answer incorrectly eligible as independent evidence.
Rejected or unacknowledged submissions retain drafts. A late review cannot affect
a newer answer. Changed teaching requires current context inside the lock.

The shared diagnostic counter covers tutor-initiated probes across nested
branches; existing initial 1..8 units and learner-requested explained extension
remain authoritative. Ordinary learner questions/direct explanation do not incur
invented assessment. Do not pretend the separate probe/check tree budgets already
enforce one global interactive budget: add and test the explicit reconciliation.

## Parallel waves and serial integration

Work in these dependency waves. A/B can prepare their independent modules in
parallel; each named slice is integrated, tested and committed separately before
the next shared-file change. Reviewer feedback may block a slice without blocking
unrelated helper work. No agent is assigned the same production file concurrently.

The proposed modules separate validation and deterministic selection from content
generation/review. They accept bounded inputs supplied by existing authorities;
they do not discover the entire vault, call a model or write ledgers. C may merge
small helpers if inspection demonstrates a better existing home, but must revise
ownership before any worker touches it. These names are planned files, not a claim
that APIs or behavior already exist.

## Independently testable slices

### P1a — purposeful Socratic turns and assistance

Select one explicit scoped capability and show one meaningful question at a time.
Use the actual latest answer/review to recommend a cue, structural hint, partial
worked step or requested full explanation. Explicit skip/explain/pause remains
available; finite budgets prevent remediation loops. Record help before its
presentation and support a new raw revision rather than replacing an answer.

Gate: confident wrong reasoning, guessed choice with wrong reason, ambiguous
response pending review, partial derivation, multiple hint levels, direct reveal,
nested prerequisite/return, budget exhaustion/approved extension, reload and
duplicate/late acknowledgements. Integrate a keyboard fixture with the existing
right question rail and central assessment cards. Do not add a chat application.
Split into P1a1 assistance persistence and P1a2 adaptive next-turn UI if the first
diff cannot be independently reviewed and verified as one unit.

### P1b — expandable explanation levels

Prepare intuitive/intermediate/formal variants for the same concept and notation,
with explicit assumptions and bridges explaining each simplification. Offer
derivation, meaning, counterexample and simpler/more rigorous requests without
requiring three lectures. Switching levels preserves assessment and current step;
reading a level never supplies evidence.

Gate: exact STAT303 finite-distribution checks, definitions/units/limits, stable
concept identity and source locators, absent variant honest fallback, narrow
screen focus/math/readability, level switch/reload/return and original draft
preservation. Keep variants within Lecture/native reader, existing stage order
and three-column desktop frame.

### P1c — adaptive tiered practice

Prepare differentiated beginner/intermediate/advanced items with capability,
dimension, criteria, valid alternative approaches, hints and verified solutions.
Select relevant practice from prerequisites/objective/evidence rather than fixed
equal sets. Exact numeric tolerances are numeric tolerances; physical units and
semantic alternatives require explicit checks or honest pending review. Never
repurpose the existing integer diagnostic `units` field as physical measurement.

Gate: meaningful tier differences, plausible distractors, reproducible numeric
checks, review-required reasoning, revision provenance, assisted versus novel
independent transfer, cumulative diagnostic budget and typed-answer recovery.
Integrate through existing question IDs/cards, not a second answer ledger.

### P1d — source synthesis, summary comparison and editing

Bind every comparison claim to an available source artifact/version/locator and
the unchanged learner summary attempt. Distinguish correct, omitted, misconception,
unsupported inference and difference of emphasis. Preserve feedback and learner
revision as separate artifacts/events. Return a targeted revision challenge;
source unavailability yields bounded refusal/limited scope, never invented content.
This implements Editor feedback for summaries; P1h extends the same provenance
principles to derivations, argument/code explanations and scientific interpretations.

Gate: accessible excerpt versus full text scope, disputed claims/uncertainty,
locator mismatch, missing source, original summary byte preservation, claim-bound
feedback, revision before optional model answer and no automatic research/evidence
promotion. Render prepared comparisons in the existing central reader; typed
responses use existing trusted submission/review flow.

### P1e — canonical terms and meaningful categories

Prepare goal-relevant source-supported terms with plain/formal meaning, examples,
locators, canonical concept links, contrasts and bilingual labels. Exact requested
counts are fulfilled only when supported; otherwise explain the supported count.
Reuse `terms.brief`/identity and glossary contracts; preparation/rendering never
calls `record_event` to award understanding. A definition is not a demonstrated use.

Gate: bilingual alias identity, term reused across sources without duplicate
concepts, insufficient source terms, defensible category membership, source
locators, meaningful diagnostic and no ledger changes just from opening content.

### P1f — optional Bloom challenges

Prepare remember/understand/apply/analyze/evaluate/create families with distinct
assessable output, criteria and legitimate alternative answers. Select by goal and
evidence; allow explicit all-six requests without requiring six completions.
Evaluate/create remain reviewed work, not exact-match scores or research approval.

Gate: six genuinely distinct cognitive demands, optional selection in Check or
practice, missing family fallback, no locked stage ladder, incomplete/alternative
answers honestly reviewed and no invented retention. Reuse c's question/rubric
validation rather than another task schema.

### P1g — honest analogies and independent transfer

Prepare explicit formal-to-analogy correspondences, where they fail, a relevance
rationale and a genuinely different transfer challenge. A replacement analogy
addresses a documented misconception without rewriting old feedback or examples.
Use research-linked box counting to distinguish geometric scaling from detector
sampling/artifacts; do not claim a measured detector slope proves fractality.

Gate: accurate mapping/breakdown, unsupported equivalence rejected, renamed worked
example not accepted as novel transfer, direct learner override, source/uncertainty
preservation, prepared offline rendering and separate reviewed learner output.

### P1h — lightweight ALTER and safe adaptation

Extend the existing recommendation/preferences path with a pure selected behavior
and bounded rationale/handoff: Advisor destination/prerequisites/cut list,
Librarian existing source inventory/availability, Tutor gap repair/practice,
Editor specific critique/revision, Roommate relevant analogy/counterexample.
Use one coordinator and cheap helpers by default. Independent specialist/source
verification remains optional where policy permits and required where existing
scientific/resource safeguards require it; do not weaken those safeguards to save
calls. Do not auto-start five agents or hide extra service costs.

Gate: unknown/current/stale/application-only evidence, learner direct request,
missing sources, time cut list with override, pending attempt precedence, reviewed
repair, completed target extension and irrelevant analogy suppression. Route
changes remain explicit at safe boundaries; answered assessment semantics and
frozen paths cannot be rewritten. Test Editor line/step/claim-specific feedback
for a derivation, summary and scientific argument, with limits of checks disclosed.
Update Study advice to explain the actual available behavior, not hypothetical
unprepared content. Startup/resume and lesson requests use the same selector.

learner pre/post/transfer/delayed evaluation and broader performance remain P3.
Keep these pending until executed. Do not reactivate overnight implementation
automation merely because this plan exists.
