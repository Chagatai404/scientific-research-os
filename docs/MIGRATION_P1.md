# P1 teaching behaviors (merged to main, not yet version-tagged)

P0 remains the released 0.9.8 baseline. P1 changes require the complete updated
helper, runtime and companion bundles together; no live installation is implied.

Optional `plan.pedagogy` adds digest-bound prepared content; absent metadata keeps
legacy behavior. Existing answers, criteria, sources and canonical records are
preserved. New `pedagogy-help` events remain raw assistance, never grades. New
question issuance checkpoints reserve diagnostic spending once across both trees.
An exhausted budget blocks only new assessments; pending answers and revisions
stay savable. Increase the budget only through the existing trusted tutoring
extension declaration with an explicit learner request and reason.

Keep full state/Markdown/HTML and draft-sidecar backups before adopting P1.
Older strict helpers do not understand the optional metadata or new help event;
do not strip assistance or raw answers merely to make an older validator accept
a session. Prefer retaining the complete newer viewer/helpers for those sessions,
or inspect a pre-upgrade backup read-only without overwriting newer work.
There is no bulk migration or automatic evidence/promotion/retention change.

The existing five-stage desktop three-column player remains. Reasoning help opens
a paged focused dialog; a refused save reveals no new hint. Revisions preserve
unsent input and prior attempts. Standalone exports acknowledge page-local progress
only and retain their download-before-closing warning. Real Obsidian acceptance
requires a separate authorized deployment and reload test; browser mocks do not
establish actual app lifecycle or learner gains. See the P1 implementation plan
for exact per-slice verification and remaining scope.

Prepared explanation levels occupy the central Lecture surface while expanded;
the original lesson resumes in place when collapsed. Opening and selection wait
for save acknowledgement, with an honest fallback on failure/missing content.
Saved choices override initial explicit depth preferences. New variants preserve
assumptions, sources and their relation to the original segment. Requests include
entry/version/segment provenance. Unpresented edits require a version increase;
after presentation, retain the old entry and author a new ID. Reading levels and
requesting an explanation never grant evidence or consume diagnostic units.


P1c adds optional prepared practice metadata and acknowledged selection checkpoints.
The existing Quiz/Check cards, diagnostic counter, drafts, raw attempts and review
writer remain authoritative. Selecting off-route practice does not rewrite the
routed lesson history. Numeric answer units are visible labels with an explicit
semantic-check limitation; only numeric tolerances are locally keyed. Written
alternatives remain tutor rubric metadata and do not become early learner hints.
Advanced items remain available explicitly. Current canonical advice may also
recommend them when its bounded target/scope/dimension exactly match the prepared
plan; old, stale or unrelated snapshots keep conservative selection. The optional
`target`/`next` advice fields preserve legacy eight-field snapshots and derive only
from the existing planner. Prerequisite-subject advice cannot authorize advancement
on the target; block/project targets need an explicit concept/capability binding. Physical/live app checks and scientific content vetting remain
separate from synthetic browser/structural tests.


P1d source comparisons require the updated complete helper, host and runtime
bundles. Supplied source text/hash/locators and prepared claims bind an unchanged
actual summary event. Feedback remains attributed to that historical attempt when
a later revision exists. A new checkpoint records feedback assistance before
presentation; synthesis is a separate explicit acknowledged reveal. Unavailable
source/unbound-attempt refusals do not record help, and an unavailable source
cannot accept either assistance checkpoint. Older strict
helpers do not understand these optional fields/checkpoints. Keep newer sessions
with their matching helpers or read pre-upgrade backups; never strip raw work or
assistance for compatibility. The central Quiz/Check surface switches between the
prepared comparison and its original card while preserving the existing frame.
No external source is fetched or independently vetted by these structural checks.


P1e vocabulary publication validates new/changed labels, canonical term/concept IDs
and source snapshots against actual local authorities under the existing lock.
Keep actual glossary/catalog files available for authoring; unchanged historical
content and raw-answer saves remain usable when those files are absent. Reading
prepared definitions never adds term events or learning credit. Optional dated
`context.vocabulary` crosses to the page only as bounded prepared term states,
with unavailable coverage distinguished from unseen. Unbound historical sessions
gain no automatic context waiver/binding. Adopt the full updated helpers, runtime
and host together; older strict context validators do not understand this field.
The route override no longer bypasses immutable issued questions or presented
teaching. Explicit legacy/unissued route changes still use their existing gate.

P1f adds optional Bloom activity sets bound to exact existing practice IDs and
versions. Update the complete helper/runtime/host bundle together before authoring
these sets or checkpoints; older strict validators reject the new family. Existing
sessions need no rewrite. A practice content version change requires an explicit
matching unpresented activity revision; presented content remains immutable. The
activity selector reuses raw answers, drafts, criterion reviews and shared budget,
and does not create six mandatory stages or six new assessments on opening All.

P1g analogies require matching updated helpers, runtime and companion. Exact
segment/practice versions and actual replacement review snapshots are immutable
bindings; old answers/reviews are preserved. Analogy reading is recorded assistance,
not independent evidence or novelty certification. The existing plan-evidence
authority determines assistance chronology. Historical replacement content stays
readable after a new raw revision, while the current recommendation no longer
attributes that old review to new work. No source fetch, detector measurement or
simulation is performed by the offline illustration.

P1h adds one deterministic ALTER-style selector (Advisor, Librarian, Tutor, Editor,
Roommate) over existing canonical advice, preferences, prepared pedagogy and actual
raw attempts. It starts no agents, calls no provider and writes no ledger; choosing a
role or prepared path only saves an acknowledged checkpoint, and "Ask the tutor"
actions send an ordinary open question. Pending written work takes precedence over
stale or unbound advice (stale advice still never authorizes advancement). Advice
currency uses the host-local calendar day that mints it. Prepared Editor critiques
bind exact lines/quotes of an actual derivation, argument or code explanation with
explicit checked/not-checked limits; summaries reuse the P1d comparison. Update the
complete helper, runtime and host bundles together. `pedagogy_revisions.py` and
`advice_freshness.py` (with their JS twins) are tested helpers that no production
path calls yet; they do not change behavior.

Course-player layout: the staged view is an outline card, a content card and a right
tool rail (Study advice, Teaching roles) on wide screens, and a compact wrapping tab
row on tablet and phone, with no scrollbars inside a stage. No stage logic changed.
Real Obsidian lifecycle and physical-device acceptance remain separate.
